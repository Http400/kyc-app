# Domain docs

This repo uses a single-context domain documentation layout.

The canonical frontend glossary is in `README.md` under
“Frontend domain glossary”. Read it before working on domain concepts,
use its terminology, and update that section when terms change.
Keep glossary definitions there rather than creating a separate `GLOSSARY.md`.

Read relevant ADRs in the root `docs/adr/` directory if present. Explain any
conflicts between proposed changes and recorded decisions. If ADRs are absent,
proceed silently; create them only when a decision needs recording.
